# 实体与数据访问

## Entity（实体层）

实体类和数据库表一一对应。

```java
@Data
@TableName("Article")
public class Article {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String title;
    private String content;
    private Long authorId;
    private LocalDateTime createTime;
}
```

### 常用注解

| 注解 | 作用 |
|---|---|
| `@Data` | Lombok —— 生成 getter/setter/toString/equals/hashCode |
| `@TableName("表名")` | 类名和表名不一致时指定 |
| `@TableId(type = IdType.AUTO)` | 主键，AUTO = 数据库自增 |
| `@TableField(exist = false)` | 非数据库字段（比如一个临时计算字段） |
| `@TableLogic` | 逻辑删除字段 |

### 分类实体

```java
@Data
@TableName("category")
public class Category {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String categoryName;  // category_name → categoryName（驼峰映射）
    private LocalDateTime createTime;
}
```

### 驼峰映射

```yaml
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
```

Entity 的 `createTime` → 数据库 `create_time`，自动映射。

### 一对多关系（文章 ↔ 分类）

文章和分类是一对多关系：一个分类下有**多篇**文章，一篇文章**只属于**一个分类。

表现在数据库：文章表存 `category_id`（逻辑外键，没有物理约束）。

### 多对多关系（文章 ↔ 标签）

文章和标签是多对多关系：一篇文章有**多个**标签，一个标签下有**多篇**文章。

关系型数据库无法直接表示多对多，需要一张**中间表**：

```
    文章表                   中间表                    标签表
    Article              Article_Tag                Tag
      id  ────────  article_id
                     tag_id      ────────  id
                                           tag_name
```

#### 中间表 Entity

```java
@Data
@TableName("Article_Tag")
public class ArticleTag {
    private Long articleId;
    private Long tagId;
}
```

没有 `@TableId`，因为 `(article_id, tag_id)` 是**联合主键**，在 SQL 中定义：

```sql
create table Article_Tag(
    article_id bigint not null,
    tag_id bigint not null,
    primary key (article_id, tag_id)
);
```

#### Mapper（空接口即可）

```java
public interface ArticleTagMapper extends BaseMapper<ArticleTag> { }
```

`BaseMapper` 的 `insert`/`delete`/`selectList` 方法都能用，因为中间表也是普通表。

#### 中间表的三种操作模式

**1. 新增关联（创建文章时）**

```java
List<Long> tagIds = request.getTagIds();
if (tagIds != null && !tagIds.isEmpty()) {
    for (Long tagId : tagIds) {
        ArticleTag at = new ArticleTag();
        at.setArticleId(article.getId());  // 注意：article 必须先 save 才有 id
        at.setTagId(tagId);
        articleTagMapper.insert(at);
    }
}
```

**先保存文章再插标签**，否则 `article.getId()` 是 null。

**2. 更新关联（修改文章时）**

```java
// 先删
LambdaQueryWrapper<ArticleTag> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(ArticleTag::getArticleId, id);
articleTagMapper.delete(wrapper);
// 再插（跟新增一样）
if (tagIds != null && !tagIds.isEmpty()) {
    for (Long tagId : tagIds) { ... }
}
```

中间表**不能直接用 update**，因为主键是组合的，你不知道哪些行要改。**先删后插**最稳妥。

**3. 删除关联（删文章 / 删标签时）**

```java
// 删文章时清理
wrapper.eq(ArticleTag::getArticleId, id);
articleTagMapper.delete(wrapper);

// 删标签时清理
wrapper.eq(ArticleTag::getTagId, id);
articleTagMapper.delete(wrapper);
```

**如果只删文章不删中间表**，`article_tag` 会有指向不存在文章的脏数据。

#### 为什么不用外键约束

当前表的定义没有 `FOREIGN KEY`，理由是：
- 删除时必须**手动清理**（代码中用 `delete` + `delete` 两步完成）
- 物理外键会影响写入性能，复杂场景下可能死锁
- 应用层保证一致性，数据库只存数据

### 点赞和收藏（用户 ↔ 文章）

点赞和收藏也是多对多关系：一个用户可以点赞/收藏多篇文章，一篇文章可以被多个用户点赞/收藏。

#### 表设计

```sql
create table Article_Like (
    user_id bigint not null,
    article_id bigint not null,
    create_time datetime,
    primary key (user_id, article_id)
);

create table Article_Collect (
    user_id bigint not null,
    article_id bigint not null,
    create_time datetime not null default current_timestamp,
    primary key (user_id, article_id)
);
```

跟 `Article_Tag` 不同的是：
- 主键是 `(user_id, article_id)` — 一个用户对一篇文章只能有一条记录
- **不需要 `@TableId`**，MyBatis-Plus 支持联合主键
- 不需要 `id` 自增字段

#### Entity

```java
@Data
@TableName("Article_Like")
public class ArticleLike {
    private Long userId;
    private Long articleId;
    private LocalDateTime createTime;
}
```

#### 查询模式：统计数量

```sql
-- 某篇文章有多少点赞
SELECT COUNT(*) FROM Article_Like WHERE article_id = ?;

-- 某个用户是否点赞了某篇文章
SELECT COUNT(*) FROM Article_Like WHERE user_id = ? AND article_id = ?;
```

这两个操作都是 `selectCount`，MyBatis-Plus 直接支持，不需要额外的 Mapper 方法。

### Notification（用户 → 用户的通知）

通知也是一对多关系：一个用户收到多条通知，一条通知只属于一个用户。

```sql
create table Notification (
    id bigint auto_increment primary key,
    user_id bigint not null,        -- 接收通知的人（文章作者）
    actor_id bigint not null,       -- 触发操作的人（点赞/收藏/评论者）
    type varchar(20) not null,      -- LIKE / COLLECT / COMMENT
    article_id bigint not null,     -- 相关文章
    is_read tinyint(1) not null default 0,
    create_time datetime not null default current_timestamp
);
```

和 `Article_Like` 不同，通知表有自增 `id` 主键，因为不是联合主键，且需要单独操作（标记已读）。

#### 关于 boolean 字段 + LambdaQueryWrapper 的坑

```java
private boolean isRead;
```

Lombok 对 `boolean` 类型的 `isRead` 生成：
- getter: `isRead()`（而不是 `getIsRead()`）
- setter: `setRead(true)`

MyBatis-Plus 用 getter 方法引用解析属性名：`isRead()` → 去掉 `is` 前缀 → 属性 `read`，去字段缓存中找字段名 `read`。

**坑：** 如果字段名是 `isRead`，缓存中是 `isRead` 不是 `read`，会报 `can not find lambda cache for this property [read]`。如果字段名改成 `read`，`SELECT is_read AS read` 又会因为 `read` 是 MySQL 保留关键字而报语法错。

**解决方案：** 字段名避开 `isXxx` 命名 + 也不是 MySQL 关键字：

```java
@TableField("is_read")
private boolean readFlag;   // ✅ 既不被 MP 截断，也不是 MySQL 关键字
```

Lombok 生成 `isReadFlag()` getter，MP 解析 `isReadFlag` → 属性 `readFlag` → 匹配字段名 ✅。SELECT 生成 `is_read AS readFlag`，`readFlag` 不是 MySQL 关键字 ✅。

在 LambdaQueryWrapper 中：
```java
wrapper.eq(Notification::isReadFlag, false);
```

**教训：** boolean 字段不要用 `isXxx` 命名，MP 的 lambda 缓存解析 getter 时会去掉 `is` 前缀，导致和实际字段名不匹配。

### User 头像字段

V12 迁移添加头像字段：

```sql
ALTER TABLE User ADD COLUMN avatar varchar(255) DEFAULT NULL COMMENT '头像URL';
```

实体类对应字段：
```java
private String avatar;
```

用户上传头像后，字段存储 URL 路径（如 `/uploads/uuid.jpg`），通过 Spring 静态资源映射直接访问。

## Mapper（数据访问层）

```java
public interface ArticleMapper extends BaseMapper<Article> { }
```

### BaseMapper 自带方法

| 方法 | 对应 SQL |
|---|---|
| `insert(entity)` | `INSERT INTO 表 VALUES ...` |
| `deleteById(id)` | `DELETE WHERE id = ?` |
| `updateById(entity)` | `UPDATE 表 SET ... WHERE id = ?` |
| `selectById(id)` | `SELECT * FROM 表 WHERE id = ?` |
| `selectList(wrapper)` | `SELECT * FROM 表 WHERE 条件` |
| `selectCount(wrapper)` | `SELECT COUNT(*) FROM 表 WHERE 条件` |

空接口就能工作，MyBatis-Plus 通过动态代理在运行时生成实现。

## MyBatis-Plus 分页插件

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

**没有这个插件**，`this.page(new Page<>(1, 10))` 不会生成 `LIMIT` / `SELECT COUNT(*)`，而是查出全部数据。

## IService / ServiceImpl

```java
public interface ArticleService extends IService<Article> { }
public class ArticleServiceImpl extends ServiceImpl<ArticleMapper, Article>
        implements ArticleService { }
```

ServiceImpl 内部持有 Mapper 对象，所以可以直接：

```java
this.save(article);        // 新增
this.removeById(id);       // 删除
this.updateById(article);  // 更新
this.getById(id);          // 查询单个
this.list(wrapper);        // 查询列表
this.page(page, wrapper);  // 分页
this.count(wrapper);       // 统计总数
this.getOptById(id);       // 查单个，返回 Optional
```
