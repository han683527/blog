# 开发工具与插件

## Lombok

编译期通过注解处理生成 getter/setter/构造器等，减少样板代码。

| 注解 | 作用 |
|---|---|
| `@Data` | 生成 getter/setter/toString/equals/hashCode |
| `@RequiredArgsConstructor` | 为 final 字段生成构造器 |
| `@AllArgsConstructor` | 为所有字段生成构造器 |
| `@NoArgsConstructor` | 生成无参构造器 |
| `@Builder` | 生成 Builder 建造者模式 |

## Hutool

Java 工具类库，本项目用于 Entity → VO 转换：

```java
List<ArticleVO> list = BeanUtil.copyToList(p.getRecords(), ArticleVO.class);
```

内部通过反射遍历源对象的 getter，找到目标对象同名字段复制过去。

## Flyway 数据库迁移

在 `resources/db/migration/` 下放 SQL 文件，应用启动时自动执行未运行过的迁移：

```
V1__create_user_table.sql
V2__create_article_table.sql
V3__create_comment_table.sql
V4__create_category_table.sql
V5__add_category_id_to_article.sql
```

**命名规则：** `V{版本号}__{描述}.sql`，版本号必须递增。Flyway 在数据库中维护一张 `flyway_schema_history` 表记录执行历史。

**`V5__add_category_id_to_article.sql`** 是新增字段的迁移，用 `ALTER TABLE` 而不是重建表：

```sql
ALTER TABLE article ADD COLUMN category_id BIGINT;
```

**不推荐用 JPA 的 `ddl-auto: update`，** 原因：
- 自动建表不可控，生产环境风险大
- 无法追踪表结构变更历史
- 多人协作时不知道谁改了表

## Swagger / Springdoc

自动生成 API 文档，访问 `http://localhost:8080/swagger-ui/index.html` 查看。

### 依赖

```xml
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.8.13</version>
</dependency>
```

版本需要和 Spring Boot 匹配，不匹配可能启动报错。

### 配置类（含 JWT 认证）

```java
@Configuration
public class SwaggerConfig {
    @Bean
    public OpenAPI blogOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("Blog API")
                        .version("1.0")
                        .description("博客项目后端接口文档"))
                // 声明全局需要 BearerAuth
                .addSecurityItem(new SecurityRequirement().addList("BearerAuth"))
                .components(new Components()
                        .addSecuritySchemes("BearerAuth", new SecurityScheme()
                                .name("BearerAuth")
                                .type(SecurityScheme.Type.HTTP)
                                .scheme("bearer")
                                .bearerFormat("JWT")));
    }
}
```

配置后在 Swagger UI 右上角出现 **Authorize** 按钮，粘贴 `Bearer <token>` 即可让需要登录的接口带上 token。

### 常用注解

| 注解 | 位置 | 作用 |
|---|---|---|
| `@Operation(summary = "xxx")` | 方法 | 描述接口用途 |
| `@Schema(description = "xxx")` | 字段 | 描述字段含义 |
| `@Parameter(description = "xxx")` | 参数 | 描述参数含义 |

### 拦截器放行

Swagger 路径必须在拦截器中放行，否则访问时被拦截返回 401：

```java
.excludePathPatterns("/swagger-ui/**", "/v3/api-docs/**");
```

## Maven 依赖管理

### 依赖坐标

```xml
<dependency>
    <groupId>com.baomidou</groupId>        <!-- 组织名 -->
    <artifactId>mybatis-plus-spring-boot3-starter</artifactId>  <!-- 项目名 -->
    <version>3.5.9</version>               <!-- 版本 -->
</dependency>
```

### scope（作用域）

| scope | 含义 |
|---|---|
| `compile`（默认） | 编译和运行时都需要 |
| `runtime` | 运行时需要，编译不需要 |
| `provided` | 编译需要，运行时由容器提供 |
| `test` | 仅测试需要 |

### 为什么有些依赖需要三个

```xml
<!-- jjwt 分三个 -->
<jjwt-api>       <!-- 接口和注解，编译时用 -->
<jjwt-impl>      <!-- 实现，运行时用 -->
<jjwt-jackson>   <!-- JSON 序列化实现 -->
```

分模块是为了让不同使用场景只依赖需要的部分。

## @SpringBootApplication

```java
@SpringBootApplication
public class BlogApplication {
    public static void main(String[] args) {
        SpringApplication.run(BlogApplication.class, args);
    }
}
```

等价于三个注解的组合：
- `@Configuration` —— 标记为配置类
- `@EnableAutoConfiguration` —— 自动配置（根据依赖自动创建 Bean）
- `@ComponentScan` —— 扫描当前包及其子包的 `@Component` 等注解

## @Component 体系

| 注解 | 用途 |
|---|---|
| `@Component` | 通用组件，Spring 托管的 Bean |
| `@Service` | 业务层（语义化，功能同 @Component） |
| `@Controller` | 控制层（语义化） |
| `@Configuration` | 配置类（语义化） |
